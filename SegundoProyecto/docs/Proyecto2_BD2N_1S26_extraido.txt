2. Resumen Ejecutivo 
Este proyecto está diseñado para que los estudiantes apliquen de manera integral sus 
competencias en el diseño, implementación y consulta de bases de datos de grafos 
utilizando Neo4j. El desafío central consiste en construir un sistema de recomendación de 
películas basado en las preferencias de los usuarios, sus relaciones sociales y patrones de 
visualización, aprovechando la capacidad de Neo4j para modelar y consultar relaciones 
complejas de forma eficiente. 
 
A partir del análisis de los requerimientos del negocio, los estudiantes deberán diseñar y 
documentar un modelo de grafos que represente usuarios, películas, géneros, actores y 
directores, junto con sus relaciones (evaluaciones, visualizaciones, amistades, actuaciones, 
direcciones). Un requisito fundamental de este proyecto es aprovechar las ventajas de las 
bases de datos de grafos, utilizando propiedades en nodos y aristas para enriquecer el 
modelo de datos.

Una vez definido el modelo, los estudiantes procederán a su implementación en Neo4j, 
creando nodos con sus propiedades y estableciendo las relaciones correspondientes. Esta 
fase incluye la configuración de la base de datos, la carga de un conjunto significativo de 
datos y la implementación de consultas Cypher que respondan a las necesidades del 
negocio. Además, deberán aplicar algoritmos de análisis de redes para calcular rutas más 
cortas entre usuarios, identificar películas populares en su red social y generar 
recomendaciones basadas en patrones de conexión. 
 
3. Enunciado del Proyecto 
3.1 Descripción del problema a resolver 
 
Los estudiantes diseñarán e implementarán una base de datos de grafos en Neo4j, 
optimizada para un sistema de recomendación de películas que considera tanto las 
preferencias individuales como las conexiones sociales entre usuarios. El problema principal 
consiste en modelar las relaciones complejas entre usuarios, películas, géneros, actores y 
directores de forma natural y eficiente, aprovechando las ventajas de las bases de datos de 
grafos. 
 
El sistema deberá garantizar: 
 
• Modelado natural de relaciones : Representación intuitiva de conexiones entre 
entidades (usuarios, películas, actores, géneros). 
 
• Consultas eficientes: Uso de Cypher para consultas que atraviesan múltiples niveles 
de relaciones. 
 
• Análisis de redes : Aplicación de algoritmos para encontrar patrones de conexión, 
rutas más cortas y comunidades. 
 
• Recomendaciones inteligentes: Generación de sugerencias basadas en relaciones 
de amigos, géneros favoritos y patrones de visualización. 
 
Las entidades principales del sistema son: 
 
Usuario: Personas que utilizan la plataforma. De cada usuario se debe guardar: Nombre, 
Email, Edad, País. 
 
Película: Contenido cinematográfico disponible en la plataforma. De cada película se debe 
guardar: Título, Año de Lanzamiento, Duración (minutos), Sinopsis. 
 
Género: Categorías cinematográficas. De cada género se debe guardar: Nombre del Género, 
Descripción. 
 

Sistemas de bases de datos 2 
 
 
Actor: Personas que actúan en las películas. De cada actor se debe guardar: Nombre, Fecha 
de Nacimiento, Nacionalidad. 
 
Director: Personas que dirigen las películas. De cada director se debe guardar: Nombre, 
Fecha de Nacimiento, Nacionalidad. 
 
Relaciones del sistema: 
 
• CALIFICÓ: Un usuario califica una película (con propiedades: puntuación [1-5], fecha, 
comentario). 
 
• VIO: Un usuario vio una película (con propiedades: fecha de visualización, completó 
[true/false]). 
 
• ES_AMIGO_DE: Relación de amistad entre usuarios (con propiedades: fecha de 
amistad). 
 
• PERTENECE_A: Una película pertenece a uno o más géneros. 
 
• ACTUÓ_EN: Un actor actuó en una película (con propiedades: nombre del personaje). 
 
• DIRIGIÓ: Un director dirigió una película. 
 
• LE_GUSTA: Un usuario tiene preferencia por un género (con propiedades: nivel de 
interés [1-5]). 
 
Reglas de negocio del sistema: 
 
1. Un usuario puede calificar y ver múltiples películas. 
 
2. Una película puede tener múltiples actores, un director y pertenecer a varios géneros. 
 
3. Los usuarios pueden tener múltiples amigos (relación bidireccional =ignorar dirección 
en match). 
 
4. Las calificaciones deben estar en el rango de 1 a 5 estrellas. 
 
5. Una película no puede tener el mismo actor interpretando el mismo personaje más de 
una vez. 
 
6. El sistema debe poder recomendar películas basándose en las calificaciones de 
amigos y géneros favoritos.

específico.

o Calcular rutas más cortas entre usuarios (grados de separación). 
 
o Identificar películas altamente conectadas (con más actores y directores

4.3 Requerimientos técnicos 
Los estudiantes utilizarán Neo4j como motor de base de datos de grafos para el diseño, 
creación y manipulación de los datos. Se podrá utilizar Python para la generación y carga 
masiva de datos mediante scripts automatizados. 
El sistema estará basado en una plataforma de streaming de películas donde se gestionan 
usuarios, contenido cinematográfico y recomendaciones personalizadas. Los requerimientos 
técnicos específicos son: 
Modelado de datos en Neo4j: 
• Identificar todas las entidades como nodos con sus propiedades correspondientes. 
• Definir las relaciones (aristas) entre nodos con propiedades que enriquezcan el 
modelo. 
• Aplicar convenciones de nombres: nodos con etiquetas en singular y CamelCase 
(Usuario, Película), relaciones en mayúsculas con guiones bajos (CALIFICÓ, VIO, 
ES_AMIGO_DE). 
• Utilizar propiedades tanto en nodos como en relaciones para almacenar información 
relevante. 
• Diseñar el modelo pensando en las consultas de negocio que se deben responder. 
Implementación en Neo4j: 
• Instalar y configurar Neo4j Desktop o Neo4j Community Edition. 
• Crear la base de datos del proyecto con configuraciones adecuadas. 
• Implementar el modelo de grafos mediante comandos Cypher CREATE. 
• Insertar datos de prueba representativos que permitan validar todas las 
funcionalidades. 

Sistemas de bases de datos 2 
 
 
Consultas Cypher: 
• Implementar todas las consultas requeridas por el negocio de forma eficiente. 
• Utilizar patrones de Cypher (MATCH, WHERE, CREATE, MERGE, SET, RETURN). 
• Aplicar funciones de agregación (COUNT, AVG, SUM) cuando sea necesario. 
• Implementar consultas que atraviesen múltiples niveles de relaciones. 
• Documentar el propósito y resultado de cada consulta implementada. 
Análisis de redes y algoritmos: 
• Implementar consultas para calcular la ruta más corta entre usuarios (shortestPath). 
• Identificar películas altamente conectadas (con más actores y directores 
reconocidos). 
Carga masiva de datos: 
• Utilizar el comando LOAD CSV de Cypher para insertar datos de forma masiva 
desde archivos CSV. 
• Crear archivos CSV bien estructurados para cada tipo de nodo y relación. 
• Utilizar MERGE para evitar duplicados en la creación de nodos. 
• Validar la integridad de los datos insertados. 
• Opcionalmente, se puede utilizar Python con la librería neo4j-driver si el estudiante 
lo prefiere.

4. Metodología 
Fase 1: Análisis de Requerimientos y Modelado Conceptual 
Los estudiantes analizarán los requerimientos del sistema de recomendación de películas, 
identificando las entidades principales (nodos), sus atributos (propiedades) y las relaciones 
entre ellas (aristas). Diseñarán el modelo conceptual de grafos considerando cómo las 
conexiones entre usuarios, películas, actores, géneros y directores permiten generar 
recomendaciones. Definirán las consultas más importantes que el sistema debe responder. 
 
Fase 2: Diseño del Modelo de Grafos para Neo4j 
Transformarán el modelo conceptual en un esquema implementable en Neo4j. Definirán las 
etiquetas de los nodos (Usuario, Película, Género, Actor, Director) y sus propiedades. 
Especificarán los tipos de relaciones (CALIFICÓ, VIO, ES_AMIGO_DE, PERTENECE_A, 
ACTUÓ_EN, DIRIGIÓ, LE_GUSTA) con sus propiedades correspondientes. Diseñarán el 
esquema considerando las consultas de negocio, optimizando la estructura para facilitar el 
traversal del grafo y el análisis de patrones. 
 
Fase 3: Configuración de Neo4j e Implementación Física 
Instalarán y configurarán Neo4j Desktop o Community Edition en su entorno de desarrollo. 
Crearán la base de datos del proyecto con las configuraciones apropiadas. Implementarán 
el modelo de grafos mediante scripts Cypher, creando constraints y índices necesarios para 
garantizar integridad y rendimiento. 
 
Fase 4: Carga Masiva de Datos 
Prepararán archivos CSV con los datos de al menos 500 usuarios, 200 películas, 100 
actores, 50 directores y 15 géneros con sus respectivas relaciones. Utilizarán el comando 
LOAD CSV de Cypher para realizar la inserción masiva de datos, aplicando MERGE para 
evitar duplicados y USING PERIODIC COMMIT para optimizar el rendimiento en grandes 
volúmenes. Como alternativa, pueden utilizar scripts en Python con la librería neo4j-driver si 
lo prefieren. Verificarán la correcta inserción de nodos y relaciones mediante consultas de 
validación. 
 
Fase 5: Implementación de Consultas Cypher 
Implementarán las 6 consultas esenciales requeridas por el negocio utilizando el lenguaje 
Cypher: calificaciones por usuario (puntuación > 4), películas de amigos no vistas, actores 
por director, géneros favoritos, recomendaciones basadas en amigos y ruta más corta entre 
usuarios. Documentarán cada consulta con su propósito, parámetros y resultados 
esperados. 
 
Fase 6: Análisis de Redes y Documentación 
Aplicarán 2 análisis de redes: calcular rutas más cortas entre usuarios (grados de 
separación) e identificar películas altamente conectadas (con más actores y directores 
reconocidos). Documentarán los resultados obtenidos, incluyendo visualizaciones del grafo, 
métricas de análisis, ejemplos de recomendaciones generadas y conclusiones sobre las 
ventajas de usar Neo4j para este tipo de problemas.
